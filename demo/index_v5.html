METRICS 字段说明

框内支持滚轮、触摸滑动或拖动滚动条查阅。

与同一条合成请求 _log_metrics 写入、再经 GET /v1/ui/last-metrics 旁路的字段 同源。 X-Req-Id 对齐本条请求。 mode：后端口径 stream（wav/pcm 流式） / non_stream_mp3。

字段数量由下游 metrics_log_mode 决定（可在 GET /v1/ui/effective-config 查看）。

  • DEV：线上精简，旁路以生产力字段为主。
  • DEBUG：追加首块上下文与 parity_mode 等诊断键（仅在后端记录了这些键时才会出现）。
ttfa_wall_ms 毫秒 · 首要关注
墙钟 TTFA（服务端）：从请求校验完成并已分配 req_id到服务端首块 PCM 进入发送链路之前的毫秒数。 含 --concurrency排队、调度等等待； ≠浏览器出声时刻，也 ≠网络 TTFB 定义。
ttfa_cuda_graphs_ms 毫秒 · 流式常见
README / benchmarks/throughput.py 与「 CUDA Graphs 流式 TTFA 」测法一致： cuda.synchronize → 首块 → synchronize。 可与官方 benchmark 对比；不含 HTTP 层在槽位之前的排队分量（更多在 ttfa_wall_ms）。
ttfa_ms DEBUG · 流式常有
首块出现时模型 timing 账本中的累计推理耗时；一般不含槽位排队。 mp3 路径中该值实为整段生成耗时（命名沿用）。
first_prefill_ms / first_decode_ms / first_overhead_ms DEBUG · 流式
首 chunk 推理拆分。 first_overhead_ms约等于 ttfa_cuda_graphs_ms − ttfa_ms（二者都有值时）。
parity_mode DEBUG · 流式
0： parity_mode=False， CUDA Graph 快路径； 1： Parity（非 Graph）。 若 --replicas < --concurrency 等触发回退，请对照启动日志 STARTUP stream_cuda_graph=。
prefill_len / attention_mask_shape / trailing_text_len / icl DEBUG
首块上下文与注意力诊断字段。
inter_chunk_max_ms / inter_chunk_p95_ms 毫秒 · 流式
相邻 PCM chunk 入队/写发送队列的间隔上限/原便善度，反映流式连续性。
rtf
实时因子：本次产出音频时长 ÷ 对应生成耗时；数值越大表示较实时跑得越快。
audio_s
本次响应合成音频总时长（秒）。
total_gen_ms
流式生成器侧累计毫秒（常作 RTF 分母）。
total_ms
服务端观测到的总墙钟毫秒（起止随 mode略有差异）。
n_chunks
流式拆分的 PCM 块数，与 stream_chunk_size、文本长度等有关。
