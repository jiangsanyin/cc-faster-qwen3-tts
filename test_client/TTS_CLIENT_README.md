# 流式TTS测试客户端使用说明

## 功能概述

这是一个带图形界面的流式TTS测试客户端，用于测试 `openai_server_v5.py` 服务的流式语音合成效果。

### 主要功能

1. **单次测试**：发送单个文本进行流式语音合成，实时播放音频
2. **性能指标展示**：
   - TTFA (Time To First Audio)：首音频延迟
   - 总耗时：从请求到完成的时间
   - 音频时长：生成的音频总时长
   - 块间间隔：inter_chunk_max / inter_chunk_p95
   - 请求成功率

## 安装依赖

```bash
pip install PyQt5 pygame requests numpy
```

## 启动方式

### Windows
双击 `run_client.bat` 或在命令行执行：
```cmd
python tts_streaming_client.py
```

### Linux/Mac
```bash
chmod +x run_client.sh
./run_client.sh
```

或直接：
```bash
python3 tts_streaming_client.py
```

## 使用说明

### 单次测试

1. 在"服务器地址"中输入服务端地址，如 `http://10.251.11.55:10018`
2. 在"音色ID"中输入注册表中的音色名称，如 `zhentong_v1`
3. 在输入文本框中输入要合成的文本
4. 点击"发送请求"
5. 观察日志和指标表格中的数据

### 并发测试

如需进行并发测试，可组织多个同事分别在各自电脑上同时运行此客户端，模拟真实的多用户并发场景。

## 关键指标说明

| 指标 | 含义 | 参考阈值 |
|------|------|---------|
| TTFB | Time To First Byte - 从发出请求到收到 HTTP 响应头的时间（网络延迟） | < 50ms (局域网) |
| TTFA | Time To First Audio - 从发出请求到收到首块音频数据的时间（包含推理+网络） | < 300ms (单路), < 500ms (多路) |
| 总耗时 | 整个请求的端到端时间 | 取决于文本长度 |
| inter_chunk_p95 | 相邻音频块间隔的95分位 | < 500ms (流畅) |
| 音频时长 | 生成的音频总时长 | - |

**重要说明：**
- **TTFB** 主要反映网络延迟，局域网通常在几十毫秒以内
- **TTFA** 包含了服务端推理时间 + 网络传输时间，是用户感知的真实延迟
- 服务端日志中的 `ttfa_ms` 是纯推理时间（不含网络），通常在 200-300ms
- 客户端的 TTFA = 服务端 ttfa_ms + 网络延迟 + HTTP 传输开销

## 测试场景建议

### 场景1：单路延迟测试
- 单个客户端测试
- 观察TTFA是否在预期范围内（通常 < 300ms）

### 场景2：多路公平性测试
- 3个同事同时在各自电脑上发起请求
- 观察各请求的TTFA差距是否合理
- 观察inter_chunk是否稳定

### 场景3：压力测试
- 4-5个同事同时在各自电脑上发起请求
- 观察错误率、TTFA分布、inter_chunk分布

## 注意事项

1. 确保服务端已启动并可访问
2. 音色ID必须在服务端的注册表中存在
3. 首次运行可能需要安装音频播放依赖
4. Windows下如果音频播放有问题，请确保安装了pygame

## 故障排查

### 无法连接服务端
- 检查服务器地址是否正确
- 检查网络连通性（ping测试）
- 检查防火墙设置

### 无法播放音频
- 确保安装了pygame：`pip install pygame`
- 检查系统音频设备是否正常

### TTFA异常高
- 检查服务端是否已完成预热
- 检查GPU是否被其他进程占用
- 检查网络延迟
